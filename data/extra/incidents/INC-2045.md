# INC-2045: Upstream column rename breaks transform_shipments and leaves shipments_fact stale

- **Date:** 2026-10-06
- **Severity:** SEV-2
- **Pipeline:** shipments_sync
- **Failed task:** transform_shipments
- **Downstream failure:** finance_reporting (check_source_freshness)
- **Duration:** 311 minutes (01:13 to 06:24 UTC)
- **Impact:** shipments_fact was not loaded for 2026-10-06 until 05:41, and the daily close report was published 24 minutes after its 06:00 UTC deadline

## Summary

On 2026-10-06 the transform_shipments task in shipments_sync failed with KeyError: 'carrier_code' on both attempts, so load_shipments_fact did not run. At 03:31 the finance_reporting task check_source_freshness failed because shipments_fact was 26h 13m old (SLA 24 hours), which stopped the daily close until the transform was fixed.

## Timeline (UTC)

- 2026-10-05 14:20 logistics-eng applied migration 0311 to the fulfilment database (carrier_code renamed to carrier_id).
- 01:08 transform_shipments attempt 1 failed; Airflow scheduled a retry.
- 01:13 Attempt 2 failed with KeyError: 'carrier_code'; load_shipments_fact was marked upstream_failed and the on-call alert fired.
- 01:31 On-call engineer acknowledged.
- 02:05 On-call compared the column list in the task log with the shipments_raw change history.
- 03:31 finance_reporting.check_source_freshness failed on shipments_fact; build_daily_close and publish_close_report did not run.
- 04:52 Fix merged: the transform maps carrier_id to carrier_code.
- 05:24 transform_shipments cleared; it succeeded at 05:26.
- 05:41 load_shipments_fact succeeded (48,213 rows).
- 05:50 check_source_freshness cleared; it passed.
- 06:24 Daily close report for 2026-10-05 published.

## Observed evidence

- Task log shipments_sync / transform_shipments / 2026-10-06 (attempt 2): KeyError: 'carrier_code' in transform step 2/4, normalize_carrier.
- The same log line before the error: "Loaded 48,213 rows from shipments_raw (columns: shipment_id, order_id, carrier_id, shipped_at, delivered_at, status, updated_at)". carrier_code is absent and carrier_id is present.
- shipments_raw schema doc, change history: on 2026-10-05 migration 0311 renamed carrier_code to carrier_id, applied at 14:20 UTC. The 2026-10-05 run (01:00 UTC) had finished before that; 2026-10-06 was the first run after it.
- Task log finance_reporting / check_source_freshness / 2026-10-06: DataQualityError: freshness check failed for table shipments_fact: max(loaded_at) is 26h 13m old, SLA is 24 hours. Latest loaded_at was 2026-10-05T01:18:27Z. orders_fact (1h 06m) and payments_fact (1h 11m) passed.
- At 02:05 max(updated_at) in shipments_raw was 2026-10-06T00:58Z, within its 6 hour SLA.

## Inferred cause

- Proposed explanation: the upstream rename of carrier_code to carrier_id broke transform_shipments, which still read carrier_code. With no load, shipments_fact kept the 2026-10-05 data, and finance_reporting's freshness check blocked the daily close.
- Supporting observations: the KeyError names the old column; the logged column list contains the new name; the failures began on the first run after migration 0311; mapping the new name made the same 48,213 input rows load.
- Confidence: high. Every link is in a log or the schema change history; only the intent of the rename is not documented.
- Alternatives considered: a stalled CDC connector, the usual cause in runbook RB-014 (Source data freshness check failed). Ruled out: shipments_raw was fresh, and the stale table was shipments_fact. Rows lost by the rename: not supported, because the row count matched after the fix.

## Resolution and verification

- Actions: following runbook RB-001 (Column renamed upstream breaks a transform), normalize_carrier now reads carrier_id and writes it to the existing carrier_code column of shipments_fact. transform_shipments, load_shipments_fact and check_source_freshness were cleared in that order.
- Verification: transform_shipments succeeded at 05:26; load_shipments_fact loaded 48,213 rows at 05:41, the same count the failed run had read; check_source_freshness passed at 05:50 with shipments_fact 9 minutes old; the close report was published at 06:24.

## Prevention

- Add a schema contract check at the start of shipments_sync that fails fast and lists missing columns (RB-001 prevention).
- Subscribe data-platform to logistics-eng schema-change announcements.
- Alert finance-data as soon as check_source_freshness fails, not at the 06:00 deadline.
