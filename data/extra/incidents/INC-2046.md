# INC-2046: Rate-limited payments pull delays payments_sync and times out the finance_reporting sensor

- **Date:** 2026-10-12
- **Severity:** SEV-2
- **Pipeline:** finance_reporting
- **Failed task:** wait_for_payments_sync
- **Upstream pipeline:** payments_sync (task pull_payments_api)
- **Duration:** 151 minutes (close report due 06:00 UTC, published 08:31 UTC)
- **Impact:** the daily close report for 2026-10-11 was 2h 31m late; payment reconciliation saw 2026-10-12 payments only after 07:49

## Summary

On 2026-10-12 the payments_sync task pull_payments_api received 29 HTTP 429 responses from api.paygate.example. It waited out each Retry-After and succeeded, but only at 07:24, so load_payments_fact finished at 07:49. The finance_reporting sensor wait_for_payments_sync, which waits for load_payments_fact, timed out at 07:30 after 4 hours.

## Timeline (UTC)

- 01:40 A manual backfill of payments_sync for 2026-10-01 to 2026-10-11 started (one backfill run at a time).
- 02:00 The scheduled payments_sync run started; pull_payments_api began at 02:00:41.
- 03:30 finance_reporting started; wait_for_payments_sync began poking every 30 minutes.
- 06:07 finance-data reported the missing close report in #data-platform-oncall.
- 06:15 On-call found the sensor still waiting and pull_payments_api retrying after HTTP 429.
- 06:22 On-call cancelled the remaining backfill dates; the backfill run already in progress finished at 07:10.
- 07:24 pull_payments_api succeeded.
- 07:30 wait_for_payments_sync failed with AirflowSensorTimeout.
- 07:37 normalize_payments succeeded; 07:49 load_payments_fact succeeded.
- 07:52 On-call cleared wait_for_payments_sync; it succeeded on its first poke.
- 08:31 Daily close report for 2026-10-11 published.

## Observed evidence

- Task log payments_sync / pull_payments_api / 2026-10-12: the first "Received 429 from api.paygate.example" came at 02:06 on page 26 (Retry-After header: 600). The progress lines show the 429 count rising steadily (7 by page 50, 25 by page 125). The run ended SUCCESS after 19,457 seconds with all 141 pages, 29 HTTP 429 responses and 4h 50m spent waiting. The task ran in default_pool.
- Task log finance_reporting / wait_for_payments_sync / 2026-10-12: the ExternalTaskSensor poked load_payments_fact 8 times at 1800 second intervals (state None each time) and failed with AirflowSensorTimeout after 14,400 seconds.
- The Airflow run list showed backfill runs of payments_sync calling pull_payments_api from 01:40 to 07:10.
- load_payments_fact for 2026-10-12 finished at 07:49, 19 minutes after the sensor's timeout.
- On 2026-10-06 the same load had finished by 02:19 (finance_reporting freshness check log).

## Inferred cause

- Proposed explanation: the backfill and the scheduled pull called the same provider API at the same time and together exceeded its rate limit. The scheduled pull slowed to 5h 24m, and the sensor's 4 hour timeout expired before payments_fact was loaded.
- Supporting observations: the first 429 came 26 minutes after the backfill started; 429s continued through the run while the backfill ran, and the pull finished 15 minutes after the last backfill run ended. On a normal day the scheduled pull and load finish within about 20 minutes.
- Contributing factor: neither follow-up of INC-2043 (Upstream API rate limit, 2026-09-16) was in place: the task still ran in default_pool rather than a shared pool for the API, and a backfill ran during the daily window.
- Confidence: medium. The provider's per-client request counts were not available, so the share of requests from the backfill is not measured.
- Alternatives considered: the provider lowered our rate limit that day. Not ruled out; its status page showed no incident, which does not exclude a quota change.

## Resolution and verification

- Actions: cancelled the remaining backfill dates, let pull_payments_api finish (no data was lost, it retried rather than failed), then cleared the sensor.
- Verification: wait_for_payments_sync succeeded at 07:52; check_source_freshness passed with payments_fact 4 minutes old; finance_daily_close for 2026-10-11 was built at 08:12 and the report published at 08:31.

## Prevention

- Created the Airflow pool paygate_api with 1 slot on 2026-10-13; pull_payments_api and its backfills now share it (runbook RB-007, Upstream API rate limit).
- Backfills of payments_sync are allowed only between 09:00 and 23:00 UTC.
- Alert finance-data at 05:30 UTC if wait_for_payments_sync is still waiting (runbook RB-011, Sensor timed out waiting for upstream).
