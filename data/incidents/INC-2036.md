# INC-2036: Database deadlock during load in orders_etl

- **Date:** 2026-08-21
- **Severity:** SEV-3
- **Pipeline:** orders_etl
- **Failed task:** load_orders_fact
- **Duration:** 56 minutes
- **Impact:** the daily sales dashboard and the finance revenue report

## Summary

On 2026-08-21, the load_orders_fact task failed in the orders_etl pipeline. Failure type: Database deadlock during load. The daily sales dashboard and the finance revenue report showed stale data until the fix.

## Timeline (UTC)

- 02:56 Alert fired: load_orders_fact failed.
- 03:06 On-call engineer acknowledged and opened the task log.
- 03:21 Root cause identified.
- 03:40 Fix applied and the failed task cleared.
- 03:52 Pipeline completed and dashboards refreshed.

## Root cause

Two jobs updated the same table in overlapping transactions touching rows in different orders (the pipeline load and the nightly reconciliation job), so Postgres aborted one as the deadlock victim.

## Resolution

Clear the failed task; a deadlock victim is safe to retry. Move the other job so schedules do not overlap.

## Follow-ups

- Always update rows in primary key order.
- Keep transactions short and avoid overlapping schedules on one table.
