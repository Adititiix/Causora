# INC-2034: Duplicate key violation on load in orders_etl

- **Date:** 2026-08-17
- **Severity:** SEV-2
- **Pipeline:** orders_etl
- **Failed task:** load_orders_fact
- **Duration:** 101 minutes
- **Impact:** the daily sales dashboard and the finance revenue report

## Summary

On 2026-08-17, the load_orders_fact task failed in the orders_etl pipeline. Failure type: Duplicate key violation on load. The daily sales dashboard and the finance revenue report showed stale data until the fix.

## Timeline (UTC)

- 02:38 Alert fired: load_orders_fact failed.
- 02:48 On-call engineer acknowledged and opened the task log.
- 03:23 Root cause identified.
- 03:58 Fix applied and the failed task cleared.
- 04:19 Pipeline completed and dashboards refreshed.

## Root cause

The load task uses a plain INSERT, so re-running it for a date that was partly loaded tried to insert rows that already exist.

## Resolution

Delete the rows for that date from the target table, then clear the task. Or change the load to an upsert (INSERT ... ON CONFLICT DO UPDATE) and re-run.

## Follow-ups

- Make every load idempotent with upserts keyed on the primary key.
- Load inside a transaction so partial writes roll back.
