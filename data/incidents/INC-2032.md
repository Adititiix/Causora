# INC-2032: Task killed for running out of memory in orders_etl

- **Date:** 2026-08-15
- **Severity:** SEV-3
- **Pipeline:** orders_etl
- **Failed task:** transform_orders
- **Duration:** 88 minutes
- **Impact:** the daily sales dashboard and the finance revenue report

## Summary

On 2026-08-15, the transform_orders task failed in the orders_etl pipeline. Failure type: Task killed for running out of memory. The daily sales dashboard and the finance revenue report showed stale data until the fix.

## Timeline (UTC)

- 02:37 Alert fired: transform_orders failed.
- 02:47 On-call engineer acknowledged and opened the task log.
- 03:16 Root cause identified.
- 03:47 Fix applied and the failed task cleared.
- 04:05 Pipeline completed and dashboards refreshed.

## Root cause

The day's data volume grew beyond the 4 GiB pod memory limit because the task loads the whole partition into memory at once.

## Resolution

Raise the memory request and limit for the task and clear it to re-run. Change the task to process the partition in chunks (for example per hour) instead of all at once.

## Follow-ups

- Alert when memory usage passes 80 percent of the limit.
- Load tests with a 2x volume before major sales events.
