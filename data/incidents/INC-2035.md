# INC-2035: Dependency version conflict after image rebuild in orders_etl

- **Date:** 2026-08-18
- **Severity:** SEV-2
- **Pipeline:** orders_etl
- **Failed task:** transform_orders
- **Duration:** 37 minutes
- **Impact:** the daily sales dashboard and the finance revenue report

## Summary

On 2026-08-18, the transform_orders task failed in the orders_etl pipeline. Failure type: Dependency version conflict after image rebuild. The daily sales dashboard and the finance revenue report showed stale data until the fix.

## Timeline (UTC)

- 02:53 Alert fired: transform_orders failed.
- 03:03 On-call engineer acknowledged and opened the task log.
- 03:09 Root cause identified.
- 03:22 Fix applied and the failed task cleared.
- 03:30 Pipeline completed and dashboards refreshed.

## Root cause

The worker image was rebuilt with an unpinned dependency, so a newer markupsafe was installed that is incompatible with the installed jinja2.

## Resolution

Roll back to the previous worker image. Clear the failed tasks.

## Follow-ups

- Use a lockfile or constraints file for every image build.
- Run a smoke test that imports all DAGs in CI before deploying an image.
