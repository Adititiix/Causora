# INC-2031: Row count dropped sharply (partial data) in orders_etl

- **Date:** 2026-08-09
- **Severity:** SEV-2
- **Pipeline:** orders_etl
- **Failed task:** validate_orders
- **Duration:** 182 minutes
- **Impact:** the daily sales dashboard and the finance revenue report

## Summary

On 2026-08-09, the validate_orders task failed in the orders_etl pipeline. Failure type: Row count dropped sharply (partial data). The daily sales dashboard and the finance revenue report showed stale data until the fix.

## Timeline (UTC)

- 02:57 Alert fired: validate_orders failed.
- 03:07 On-call engineer acknowledged and opened the task log.
- 04:18 Root cause identified.
- 05:22 Fix applied and the failed task cleared.
- 05:59 Pipeline completed and dashboards refreshed.

## Root cause

The extract was only partial (some export shards were missing or the extract query filtered too much), so far fewer rows than normal reached the check.

## Resolution

Do not load the partial data. Then re-run the check and the load.

## Follow-ups

- Compare row counts against the source before loading.
- Keep the 40 percent drop check as a hard gate.
